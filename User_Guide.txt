==========================================
 Hotel Pricing Assistant
 User Guide
==========================================

IMPORTANT: DEMO DATA
--------------------
Unless your administrator has configured PMS credentials, this tool runs in
DEMO MODE. Bookings, competitor prices and base rates are synthetic examples.
The top-right corner of the window shows the current data mode. Do NOT publish
these rates to a booking channel. See README.md for how to connect a live PMS.

DAILY WORKFLOW
--------------
1. Double-click "Start_Pricing_UI.bat" to open the app window.
2. Click "Run Pricing Now" (top-left).
3. Wait for the dark log box at the bottom to say "[OK] Pricing finished".
   The table refreshes with recommended rates for the next 90 days, by room
   type.
4. Click ANY row to see WHY that price was set:
   - A one-line summary of the recommended rate and how much it moved
   - A bar chart comparing the base rate with the recommended rate
   - Five factor cards: Special Event / Supply & Demand / Booking Pace /
     Competitor / Forecast RevPAR. The Special Event card shows the event
     factor from the calendar (for example "Factor: 1.50x").
   - A confidence score (below 70 means use your own judgement too)
5. Use the dropdowns above the table to filter by date range or room type.

TIMEZONE (SECOND ROW, UNDER THE BUTTONS)
---------------------------------------
The "Timezone" dropdown sits on its own row just below the top buttons.
Selecting an entry takes effect immediately - there is no Apply button - and
pricing runs again automatically so the table matches the new timezone.

The sentence on the right always shows which timezone is in use and what it
affects: the rates, the current pricing date and the daily 06:00 run. Keep an
eye on it; it tells you which day the prices were calculated for.

The default "Follow local system time" needs no setup. Named timezones need
the IANA timezone database; if it is missing, the app tells your administrator
to run "pip install tzdata" and keeps the local-time setting. A change is
picked up by a running scheduler within about a minute, with no restart.

ADD OR CHANGE A SPECIAL EVENT (NO CODING NEEDED)
-----------------------------------------------
All public holidays and special events live in "Public holidays.csv" in the
same folder. This file works every year; you only maintain the dates.

1. Click "Open Event Calendar" in the app. The CSV opens in Excel or Notepad.
2. Add one row per special date, for example:
       2027-02-06,Chinese New Year Day 1,1.40,Public Holiday,N
   Columns are: Date, Event_Name, Event_Factor, Category, Recurring
   - Date:         YYYY-MM-DD for a one-off date.
                   Use MM-DD with Recurring=Y for a date that repeats yearly
                   (for example 12-25,Christmas Day,1.50,Public Holiday,Y).
   - Event_Factor: 1.00 = no change, 1.25 = +25%, 0.90 = -10%.
                   Must be greater than 0. Values outside 0.50-3.00 still
                   work but produce a warning.
   - Category:     Public Holiday, Special Event, School Holiday or Custom.
   - Event_Name:   May be left empty. An empty name shows the reason
                   "Public Holiday Demand Window Triggered" in the report.
3. Save the file as UTF-8 CSV, then click "Run Pricing Now" again.
   The new factor applies immediately to the matching stay dates.

Useful rules:
   - A specific YYYY-MM-DD row overrides a yearly MM-DD row on that date.
   - If two rows share the same date, the last one wins.
   - Lines starting with # are notes and are ignored.
   - Only dates inside the next 90 days affect prices.
   - If the file is missing or a row is invalid, the run stops with a clear
     error message and a line number. Fix the file and run again.

EVERY YEAR (IMPORTANT)
----------------------
Fixed dates (New Year, Labour Day, National Day, Christmas, New Year's Eve)
repeat automatically and need no work. The following dates MOVE every year
and must be added as new YYYY-MM-DD rows before each new year:
   Chinese New Year, Hari Raya Puasa, Hari Raya Haji, Vesak Day, Deepavali,
   the Singapore Grand Prix weekend, school holiday periods and
   observed-in-lieu holidays.
Use the official Singapore public holiday calendar and the F1 race calendar.
The dark log box prints a warning if a covered year has no one-off rows yet.

TABLE ROW COLORS
----------------
Red    = Peak Demand
Orange = High Demand
Green  = Low Demand

PRICING REASONS YOU MAY SEE
---------------------------
"Public Holiday Demand: <name>"         a named holiday or event was applied
"Special Event Demand: <name>"          a named special event was applied
"Public Holiday Demand Window Triggered" a calendar row has no Event_Name
"| Rate ceiling applied"               the upper rate guard limited the price
"| Rate floor applied"                 the lower rate guard limited the price
Other reasons cover occupancy, booking pace, competitor pricing and stable
market conditions.

PREFER NOT TO USE THE WINDOW?
-----------------------------
Double-click "Run_Pricing_Now.bat" to run one pricing cycle directly.
The daily 06:00 run happens automatically via scheduler.py, in the timezone
chosen in the staff UI (this computer's local time by default). A change is
picked up within about a minute without restarting the scheduler.

TROUBLESHOOTING
---------------
Q: The log says "[ERROR] Event calendar not found" or shows a line number?
   Open "Public holidays.csv" and fix the reported row. The engine will not
   produce rates from an incomplete calendar.
Q: Nothing happens / an error in the log?
   Screenshot the dark log box and send it to your system administrator.
Q: A result file is open in Excel - will it fail?
   No. The engine saves to an alternative timestamped filename.
Q: The rate looks lower than the base rate on a holiday?
   Check the factor cards: demand, pace and same-day discounts can outweigh
   the event uplift. The Special Event card confirms the event factor was
   applied. Remember this is demo booking data.
Q: Choosing a timezone shows "Timezone data not available"?
   Ask your administrator to run "pip install tzdata", then reopen the
   window. Alternatively keep "Follow local system time", which needs no
   extra package.
Q: The dates in the table shifted after switching timezone?
   Expected: the 90-day window starts on the current date in the selected
   timezone, so crossing the date line moves it by one day.
